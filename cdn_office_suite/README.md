# Office Suite launcher

A responsive launcher for Wordcraft, Gridcraft, Deckcraft, PDFcraft, Vectorcraft, CADcraft, Photocraft and the server's existing mail. See the [root README](../README.md) for the full suite and installer documentation.

`index.html` contains the public app cards and readiness/maintenance status. `office.css` supplies warm colours, official artwork, playful details, keyboard focus and reduced-motion styles. `assets/images/*-icon.png` are the official app icons used by cards and copied into the shared host for browser favicons.

`updates.html` is the administrator shell, opened separately from the launcher. Actual controls come from the protected host endpoint after OC4D superadmin authorization. Progress polling reconnects automatically, retains the last visible progress during outages and restores saved server state. Approval is explicit; ordinary users cannot install updates.

`settings.js` is generated by the installer and contains only office/mail port configuration. It has no authentication secrets. The launcher reads the existing OC4D browser session; all privileges are verified on the server.

The installer copies this directory into `<website-dir>/public/modules/cdn_office_suite`. It replaces the old Etherpad/Ethercalc launcher links and removes their fallback pages. The outdated Mobirise project for those old tools has been retired. App processing and saved work belong to the browser/device; the launcher does not provide shared document storage.

`connection.js` validates all three configured ports, rejects missing/colliding values and constructs explicit office/mail URLs. It takes an immutable copy of the settings so later changes to the input object cannot redirect requests. No guessed-port fallback is used. All seven Craft app routes use the configured shared office port; the existing mail link uses its own configured port.

For encoded OC4D Gateway nip.io hostnames, connection.js changes the port encoded in the hostname and retains the gateway's public scheme/port. It does not send app traffic directly to the gateway's backend port. Requests include gateway cookies, and the matching gateway Origin/CORS translation fix is required. Direct LAN routing is unchanged. Gateway cookies remain scoped by hostname; open/sign into a Craft route if remote status or updates cannot reach the office-host session.
